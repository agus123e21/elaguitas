Arquitectura del Sistema

Cómo se conectan las partes del sistema

El sistema respeta el modelo Cliente - Servidor separando claramente la pantalla, el servidor y la base de datos:

1. La Pantalla (Frontend)
React + Vite

La interfaz visual que usa el cliente, el chofer o el administrador desde su teléfono o PC.

  • Rápida e interactiva: no recarga la página.
  • Diseño Mobile-First: optimizada para celulares.
  • Validación visual: evita campos vacíos o errores.
2. El Servidor (Backend)
Node.js + Express

El "cerebro" del sistema. Recibe los pedidos, calcula los precios y aplica las reglas del negocio.

  • Verificación de acceso: controla usuarios y claves.
  • Lógica de stock: descuenta el agua vendida.
  • Balance de envases: computa los vacíos devueltos.
3. La Base de Datos
PostgreSQL en Supabase

Donde se almacena toda la información de forma permanente en tablas relacionadas.

  • Tablas relacionadas: con claves PRIMARY KEY y FOREIGN KEY.
  • Consultas protegidas: seguras contra inyecciones SQL.
  • Conexión en la nube: base PostgreSQL hosteada en Supabase.
Arquitectura · Comunicación y Conexiones

Comunicación en Capas: Frontend → Servidor → Base de Datos

Cómo viaja la información desde que el usuario hace un clic hasta que impacta en las tablas:

1
Petición desde la Pantalla
Frontend (React)

El usuario aprieta un botón (por ejemplo, confirmar pedido) y el navegador arma un paquete de datos en formato JSON.

POST /api/pedidos { id_cliente: 4, items: [...] }
2
Procesamiento en Servidor
Backend (Express)

El servidor recibe el pedido, comprueba la identidad del usuario, valida que haya stock y prepara la consulta hacia la base de datos.

pool.query('UPDATE stock...')
3
Persistencia en Supabase
PostgreSQL Engine

La base de datos ejecuta la operación mediante un pool de conexiones seguro y devuelve la respuesta confirmada.

HTTP 201 { mensaje: "Pedido creado con éxito" }
Desacoplamiento total: Si mañana se crea una aplicación móvil o se cambia el diseño visual, el servidor y la base de datos siguen funcionando exactamente igual sin modificarse.
Base de Datos Relacional · Modelo de Datos

Las 3 tablas principales & Estructura SQL

Cumpliendo con la consigna, la base de datos cuenta con tres tablas maestras relacionadas entre sí:

1. Tabla `usuarios`
Clientes, Choferes y Admin
id INT PRIMARY KEY
nombre VARCHAR(100)
email VARCHAR(120) UNIQUE
password VARCHAR(255)
rol VARCHAR(20)
saldo_envases INT DEFAULT 0
SELECT * FROM usuarios WHERE email = $1;
2. Tabla `productos`
Catálogo de Agua y Stock
id INT PRIMARY KEY
nombre VARCHAR(100)
precio DECIMAL(10,2)
stock INT CHECK >= 0
es_retornable BOOLEAN
UPDATE productos SET stock = stock - 2 WHERE id = 1;

Cabecera y Detalle de Venta
id INT PRIMARY KEY
id_cliente FOREIGN KEY (usuarios)
id_chofer FOREIGN KEY (usuarios)
estado VARCHAR(20)
total DECIMAL(10,2)
envases_retirados INT
INSERT INTO pedidos (id_cliente, total, estado) VALUES (...);

Módulo Integrador de Procesamiento

¿Cómo procesa el sistema un nuevo pedido?

El módulo integrador cruza las 3 tablas principales: comprueba stock en planta, descuenta unidades, calcula envases vacíos y guarda el registro:

1
Verifica Stock

Revisa que haya suficientes bidones en la planta antes de aceptar el pedido del cliente.

SELECT stock FROM productos...
2
Descuenta Stock

Resta de inmediato los bidones solicitados para que nadie más pueda comprarlos.

UPDATE productos SET stock = ...
3
Balance Vacíos

Si entrega los vacíos, paga solo el agua. Si no tiene envase, se le cobra el recambio.

vacios_entregados vs pedidos
4
Guarda Venta

Guarda la cabecera y el detalle en pedidos para que el chofer lo despache.

INSERT INTO pedidos...
Consistencia garantizada: Si un pedido se cancela, el stock y los envases vuelven automáticamente a su estado original en la base de datos.
Seguridad y Control de Acceso

Seguridad, contraseñas y permisos por rol

El sistema protege la información confidencial y asegura que cada usuario solo acceda a sus funciones permitidas:

1. Claves Encriptadas
Bcrypt (Hash + Salt)

Las contraseñas nunca se guardan en texto plano. Se transforman en un código hash seguro e irreversible.

  • Nadie puede leer las claves en la base de datos.
  • Se verifican de forma matemática al iniciar sesión.
2. Sesión Segura
Tokens Firmados (JWT)

Al iniciar sesión correctamente, el sistema entrega una llave digital de acceso temporal.

  • Identifica al usuario sin pedir la contraseña a cada rato.
  • Vence automáticamente al cerrar sesión o por tiempo.
3. Permisos por Rol
Admin · Chofer · Cliente

Cada sección privada está restringida según el rol de la persona:

  • Cliente: Solo pide agua y ve sus compras.
  • Chofer: Solo ve los pedidos asignados en su ruta.
  • Admin: Controla precios, usuarios y despacho.
